# 盐城中学 · 盐中之声 每日点歌系统

Cloudflare Pages + Pages Functions + D1 的点歌 / 投票系统，部署在 `vote.yzstu.top`。

本包是**整体替换版**：把仓库里的文件全部覆盖即可，不需要挑文件。

---

## 一、部署步骤

### 1. 整体替换仓库内容

把本目录下的**全部文件**覆盖到仓库根目录（含 `assets/`、`functions/`、`_lib/`、`sql/`），
然后提交，Cloudflare 会自动重新部署。

> 注意：必须**整体替换**。`assets/` 里只有两张页面真正引用的图：
> `school-badge.png`（右上角校徽）与 `radio-logo.png`（盐中之声）。
> 旧仓库里多出来的 `Image_*.png`、`zf1.png`（1 字节空文件）等都可以删掉。

### 2. 在 D1 控制台执行 SQL

按顺序全部执行一遍（`sql/001` ~ `sql/009`）。方便起见也可以直接粘贴交付目录里的：

- `操作.txt` —— **全新部署**用，99 行纯 SQL，从 001 到 009 全量。
- `操作-增量补丁.txt` —— **已经跑过 001~003** 的话只跑这个，18 行（004~009）。

> 注意：完整版不要重复执行：`ALTER TABLE ... ADD COLUMN` 在列已存在时会报错并中断，
> 后面的语句就跑不到了。

### 3. 配置环境变量（可选但建议）

在 Pages → Settings → Environment variables 里加：

| 变量 | 作用 | 不配的后果 |
|---|---|---|
| `AUTH_PEPPER` | 随机字符串。班级口令的查找索引与可查看密文都由它派生 | 会退回源码里的默认值，等于少一层保护 |
| `RECAPTCHA_SITE_KEY` | reCAPTCHA 站点密钥（公开） | 不配则**不启用**人机校验 |
| `RECAPTCHA_SECRET` | reCAPTCHA 密钥（**保密**，别提交到仓库） | 同上 |
| `RECAPTCHA_STRICT` | 设成 `1` 表示"没令牌也拒绝" | 默认 `0`：拿不到令牌时放行（见下文） |
| `RECAPTCHA_MIN_SCORE` | v3 分数阈值，默认 `0.5` | 低于它判为机器人 |
| `RECAPTCHA_BASE` | 覆盖校验域名 | 默认 `https://www.recaptcha.net` |
| `DEBUG_LOGIN` | 设成 `1` 才启用「管理员账号:密码」调试登录 | **默认关闭**，生产留空即可 |
| `GUEST_PASSWORD` | 游客口令。配了才有「游客模式」（只读：能看排行与试听） | **默认关闭**：不配就等于没有游客模式 |
| `TRACK_TOKEN_SECRET` | 选曲凭据的签名密钥 | 退回用 `AUTH_PEPPER`，一般不用单独配 |
| `ICP_BEIAN` / `GONGAN_BEIAN` / `COPYRIGHT_HOLDER` | 备案号与版权主体 | 页面里已写死真实值，配了就以环境变量为准 |
| `MUSIC_PROVIDER` | `auto`（默认）/ `meting` / `apple` | 默认 `auto`：优先 Meting，失败回退苹果官方试听 |
| `MUSIC_API_BASE` | 自建 Meting 地址 | 用内置的公共 Meting 源 |
| `MUSIC_STOREFRONT` | 苹果试听的地区，如 `hk` / `tw` / `us` | 默认即可 |

#### 人机校验（reCAPTCHA v3）

**域名是这套功能能不能用的关键。** 实测（中国大陆网络）：

| 域名 | 结果 |
|---|---|
| `www.google.com/recaptcha/api.js` | **超时（被墙）** |
| `www.recaptcha.net/recaptcha/api.js` | HTTP 200，约 200ms |

`recaptcha.net` 是 Google 官方为这类地区提供的**备用域名，功能完全一致**。
本项目默认走 `www.recaptcha.net`；若用了 `google.com`，学生浏览器加载不出脚本、
拿不到令牌，投稿功能会直接不可用。

**降级策略（避免"墙一抖全校都投不了稿"）：**

| 情况 | 行为 |
|---|---|
| 没配 `RECAPTCHA_SECRET` | 完全不启用，直接放行 |
| 前端拿不到令牌（脚本被墙） | **默认放行**；设 `RECAPTCHA_STRICT=1` 可改成拒绝 |
| 令牌无效，或 v3 分数低于阈值 | **拒绝** |
| 校验服务本身不可达 | 放行（网络抖动不该让功能全挂） |

前端**不写死任何密钥**：站点密钥由公开接口 `GET /api/config` 下发，
`RECAPTCHA_SECRET` 只在服务端读取。CSP 里已放行 `recaptcha.net` 的脚本、
徽标 iframe 与校验请求（见 `_headers`）。

> 注意：**不要随意更换 `AUTH_PEPPER`。** 查找索引和可查看密文都由它派生，
> 换了之后所有已有班级口令会失效、旧密文也解不开。万一换了：
> 管理员仍能登录（管理员登录不依赖查找索引），到后台把班级口令
> **逐个重设**或**批量重新生成**一遍即可恢复。

## 二、这次修掉的安全问题

交接文档里那位群友找到的洞，逐条处理如下：

| # | 问题 | 处理 |
|---|---|---|
| 1 | **存储型 XSS**：歌名/歌手直接拼进 `innerHTML`，可注入脚本偷管理员密码 | 前端所有插值走 `escapeHtml()`；后端 `_lib/validate.js` 入库前拒绝 `<` `>`；`_headers` 加 CSP 兜底 |
| 2 | **明文口令**：`classes.password` 明文存库 | 改为加盐 **PBKDF2-SHA256**（10000 次）。旧明文/旧 SHA-256 在登录时自动升级 |
| 3 | **鉴权形同虚设**：前端把口令存 `sessionStorage`，接口只看字段非空 | 改为**服务端会话**：HttpOnly Cookie，令牌只存 SHA-256 摘要 |
| 4 | **防刷票可绕过**：只比 `User-Agent`，改 UA 即可重复点歌 | 改用**设备指纹**（Canvas + WebGL + 屏幕/时区/核数）按设备去重 |
| 5 | `/api/admin-list` **无认证**，任何人可读内部数据 | 加管理员会话校验 |
| 6 | 黑名单 SQL 的 `AND`/`OR` 优先级写错，过期时间失效 | 改写为单条 `instr` 字面包含 |
| 7 | 黑名单 `LIKE` 方向反了，歌手名后加一个字符即可绕过 | 同上 |
| 8 | 点歌是"先查重再写入"，并发可穿透 | 合并成单条原子 `INSERT ... SELECT ... WHERE NOT EXISTS` |
| 9 | 投票是先查后插，同一设备可并发刷票 | `INSERT OR IGNORE` + `meta.changes` 原子判定 |

另外修掉的：搜索接口的 SSRF（客户端不能指定上游 URL）、
管理接口越权（普通管理员不能改他人密码）、各类越界与非法值校验。

## 三、功能说明

### 多口令的语义（这里踩过坑，重要）

**多个班级口令 = 多把进同一个系统的钥匙，不是多套互不相通的数据。**

全校共用**一份榜单**：任何口令登录看到的都是同样的歌，点歌查重也是全校范围。
`class_id` 只用来在后台标注"这是哪个班点的"，**不参与可见性判断**。

> 早期版本把 `class_id` 当成租户隔离条件（`WHERE s.class_id = ?`），
> 结果新加一个口令登录后榜单就是空的。已修正。

### 多管理员系统

| 角色 | 怎么来的 | 能做什么 |
|---|---|---|
| **高级管理员** `super` | 初始 `admin` 账号（003 迁移里提升） | 全部：审核、公告、分类权重、班级口令、黑名单、生成动态口令、删除管理员 |
| **普通管理员** `admin` | 用动态口令在 `/register.html` 自助注册 | 审核歌单、维护黑名单、发公告 |

- **动态口令**（邀请码）由高级管理员在「系统设置」里生成，**只显示一次**（库里只存哈希）。
  把它给同事，对方打开 `/register.html` 填进去即可注册，支持 `?code=` 预填。
- 角色**以数据库当前值为准**，改角色立即生效、不必重新登录。
- 历史数据里 `role` 为空的账号按高级管理员对待（旧库只有一个全权管理员）；
  无法识别的取值按最低权限处理，避免意外提权。

### 公告区

管理员可发公告，学生在**首页**看到（下架的公告学生看不到）。
管理在「系统设置 → 发布公告」，支持编辑、上下架、删除。

### 回收站 ≠ 黑名单

两个完全独立的东西，界面上也分开写了：

- **回收站**：`songs` 表里 `status='rejected'` 的歌曲。可逐首**恢复**或**彻底删除**，
  也有**一键清空回收站**。彻底删除会同时清掉它的举报与投票记录。
- **黑名单**：`banned_items` 表，是**违禁词**清单，不含任何歌曲记录，也不会删除已有歌曲。
  支持 30 / 90 / 365 天或长期，到期自动解禁。

### 黑名单只能封违禁词，不能封具体的歌曲

这是刻意的设计约束，不是遗漏：

- 匹配时把「歌名 + 歌手」拼成整串做**字面包含**，词出现在哪一边都算命中。
  - 所以**没有**"只封歌名"或"只封歌手"这种选项 —— 历史数据里的 `type` 列保留但
    **不参与匹配**，避免有人靠"只封歌名"把某首歌单独做掉。
- 单个违禁词**最多 12 个字**。一整首歌名基本都会超过这个长度，粘不进来。
  超长会明确提示："黑名单是用来封违禁词的，不是用来封某一首歌的 ——
  要下架某首歌，请到「待审核 / 回收站」里处理。"
- 要下架某一首歌，正确路径是：审核时不通过（进回收站），或把已通过的歌移入回收站。

判定顺序也保证违禁词不会被绕过：**先过违禁词，再看音源 id 和调试模式**，
所以哪怕点歌时带了 `track_id`、或用管理员身份进调试模式，违禁词一样拦得住。
违禁词通过之后，歌曲**依然只是 `pending`**，照常要人工审核 —— 选了音源 ≠ 免审核。

### 班级口令的查看与分发

班级口令是要发到各个班去的，所以管理员**必须随时能查到**。只存 PBKDF2 哈希的话
管理员自己也拿不回来，因此口令存两份：

| 列 | 内容 | 用途 |
|---|---|---|
| `password` | 加盐 PBKDF2 哈希 | 登录校验，不可逆 |
| `password_encrypted` | **AES-GCM 密文** | 仅用于管理员在后台查看与复制 |

密钥由 `AUTH_PEPPER` 派生，**存在环境变量里而不是数据库里**，所以只拿到数据库
（没有环境变量）依然解不开，比直接存明文强得多。

- 只有**高级管理员**能看到口令；普通管理员看到的是"仅高级管理员可见"。
- 后台「班级口令列表」每行都有口令和「复制」按钮，勾选可**批量删除**。
- 已存在的旧口令（哈希不可逆）没法自动补密文，列表会提示"点修改口令重设一次"。

### 一键批量生成班级口令

「系统设置 → 一键批量生成班级口令」，填年级、名称前缀、序号范围、每班人数，
一次生成如 高一(1)班 ~ 高一(20)班。

- 可选「每班一个随机口令」或「所有班共用一个口令」。
- 口令生成后**随时可以在班级口令列表里查看和复制**，不必当场抄下来。
- 生成是前端逐个调接口的：20 个班级 = 20 次 PBKDF2，放在服务端会超过免费套餐
  的单次 10ms CPU 限制。

### 年级 / 人数 / 投票上限

班级多了两个管理员可填的字段：**年级**（如「高一」）与**人数**。

- 后台「班级口令列表」**按年级分组**展示，每组显示"共 N 个班 · 已填 M 个班共 X 人"。
- 每个班有「改年级/人数」按钮；批量生成时也能一次填好。
- 系统把所有班级人数**汇总成全校总人数**，显示在「投票上限」卡片里。

**投票上限的规则：超过上限的那部分票不计入票数。**

- 后台「投票上限（超出部分不计入）」填一个数字，点「保存上限」；
  可点「填入汇总人数」直接把汇总结果填进去。填 **0 表示不限制**。
- 生效方式：票照收、数据库原始票数不变，但**学生端显示的票数与正式榜排序都用封顶后的值**。
  例如上限 900、实际 1200 票，学生看到 900 票；接口里仍带 `votes_raw` 与 `votes_capped` 供排查。

### 举报与举报收件箱

学生在**待审核列表**里每首歌都有「举报」按钮，可填原因（选填）。

**只有被多次举报、且仍然有效的举报才会进收件箱**：

- **多次**：同一首歌被**不同班级**举报次数 ≥ 阈值（默认 3，后台可调 2–20）。
  同一班级对同一首歌只能举报一次（唯一索引保证）。
- **有效**：歌还在待审核池里（`status='pending'`），且这条举报还没被处理过。
  已被审核掉的歌，即使被举报过也不再出现。

所以一个学生随手举报一次不会打扰管理员，多人反映的才会浮上来。

**位置**：「待审核」页签顶部的红色卡片「举报收件箱」。每条显示歌名歌手、
**被几个班级举报**、当前票数，以及**每条举报的明细**（哪个班、什么原因、什么时候）。
可直接「通过 / 拒绝 / 标记已处理」。点「标记已处理」后这批举报不再显示
（歌曲本身不动，仍在待审核列表里），同时清掉它的「已被举报」标记。

### 点歌必须从列表里选，选中后锁定音源

点歌页的**歌名框本身就是搜索框**：直接在里面输入歌名或歌手的一部分
（比如「七里」），回车或点「搜索歌曲」就会搜。后端做了三级降级
（歌名+歌手 → 只按歌名 → 模糊搜索），输入不全也能找到。

- 搜索结果里点「选这首」，会把完整歌名写回框里、歌手填进下面的框，
  并把那首歌的**音源 id 藏进隐藏字段**（页面上不显示）。
- 歌手框是**只读**的 —— 它是"已选中"的展示位，不是输入框。
- 没选就提交会被拦下，提示区分两种情况：框里只是关键词 vs 什么都没输入。
- 选完之后又手动改了歌名，提交时会拦下并提示重新确认，
  避免出现"显示的是一首、实际锁定的音源是另一首"。
- 后端也会校验（没有 `track_id` 直接 400），前端拦不住时还有兜底。

**好处**：这首歌上榜后，任何人点「试听」**直接播放当初锁定的那一版**，
不再重新搜索再让人挑。播放面板底部留了「这首不对？换个版本」作为退路。
历史数据没有 `track_id`，前端会自动退回"搜索 + 候选列表"的老流程。

### 试听

排行榜页（每首歌）、点歌页（「搜索歌曲」与「▶ 先试听一下」）、
以及后台三个页签（待审核 / 已通过 / 回收站）都有试听。

**试听面板的结构：顶部一个固定播放器 + 下面一份音乐列表。**

- 播放器固定在面板**顶部**：点列表里任意一行都只替换它的内容并高亮那一行。
- 音乐列表每行：序号、歌名、歌手 · 专辑 · 来源、时长、播放按钮。
- 面板本身和榜单卡片明显区分：左侧品牌色竖条 + 淡蓝底 + 标题数量
  （如「试听候选 · 8 个」）+ 右上角固定的**「收起 ▲」**。

点歌页的搜索面板和试听面板**都能「选这首」把数据填回表单**，且只填表不自动提交。

### 调试模式（用管理员身份在学生端点歌）

在**主页的班级口令输入框**里输入：

```
管理员账号 空格或冒号 管理员密码
```

例如 `admin:admin888` 或 `admin admin888`。通过后即进入调试模式：

> **两个前置条件（审计 A5 之后新增）**：
> 1. 必须在环境变量里设 `DEBUG_LOGIN=1` —— **默认是关闭的**。
>    这样「忘记配环境变量」落在安全那一侧，而不是让每个部署都开着后门。
> 2. 必须用**高级管理员**（role 为 super）的账号。普通管理员不能进调试模式 ——
>    这条身份能不限次、不查重地写真实歌曲表，不该开放给普通管理员。
>
> 调试会话会记录**归属管理员**（`sessions.debug_admin_id`），
> 改密 / 删号 / 登出时会一并撤销。学生榜单也会排除 `is_debug` 的歌。

- **点歌不限次数**，不占用"每人每周一次"额度；
- **不查重**，同一首歌可反复提交，方便测试；
- 提交的歌标记 `is_debug=1`，后台显示紫色**「调试模式」**，班级显示为"调试"；
- **与已有正式歌曲同名同歌手的调试歌曲不出现在审核列表里**（调试时会反复提交，
  不隐藏会刷屏）；不重复的调试歌曲正常显示。
- 违禁词规则仍然生效，方便顺便验证过滤。

调试会话有效期 2 小时，走和普通学生一样的 HttpOnly Cookie，不影响后台登录态。

### 游客模式（只读口令，环境变量 `GUEST_PASSWORD`）

**用途**：让没拿到班级口令的人（家长、外校同学、来参观的老师）只**看排行**，
不能投稿、不能投票、不能举报。

| | 说明 |
|---|---|
| 怎么开 | 在 Pages → Settings → Environment variables 里加 `GUEST_PASSWORD`，值就是游客口令 |
| 怎么关 | **删掉这个变量**（或留空）。默认就是关闭的 |
| 登录入口 | 和班级口令**共用首页那一个输入框**，不用记两个入口 |
| 判定顺序 | 先按班级口令查，查不到再比 `GUEST_PASSWORD`；两者写成同一串时按**班级**登录 |
| 会话 | 复用学生那一侧（`yczx_class_session` Cookie），`role='guest'`、`subject_id=0` |

**能做什么 / 不能做什么**（服务端逐条拦，不是只把按钮变灰）：

| 接口 | 游客 |
|---|---|
| `GET /api/rank`（看排行） | 允许 |
| `GET /api/music`（试听） | 允许。**这是有意的判断**：试听只是一个只读代理，而且榜单里每首歌就带试听按钮；禁掉它会让"只能看排行"变得很别扭 |
| `GET /api/announcements`（公告） | 允许 |
| `POST /api/vote`（投稿） | **403**「游客模式只能查看排行，不能投稿」 |
| `POST /api/upvote`（投票） | **403**「…不能投票」 |
| `POST /api/report`（举报） | **403**「…不能举报」 |
| `POST /api/suggest`（歌曲建议） | **403**「…不能提建议」 |
| `POST /api/schedule`（排期） | **403**「…不能排期」（本来就是管理员专属） |

闸门统一放在读请求体、限流计数与任何写入**之前**，所以被拒的请求
连一次限流计数、一行数据库记录都不会留下（测试就是这么断言的）。

前端配合（只是体验层，真正的闸门在服务端）：

- 首页顶部显示一条提示：「当前为游客模式，只能查看排行（榜单里的试听仍然可用）；不能投稿、投票或举报。」
- 「去投稿」/「投票」/「举报」置灰。用的是 `disabled` 属性而不是"把颜色调淡"：
  按钮直接不再派发点击，「去投稿」是链接所以同时去掉 `href`（没有 `href` 的链接
  键盘也进不去），并补 `aria-disabled` 与说明原因的 `title`。
- 点歌页：提交按钮**默认就是禁用的**，进页面先问身份再决定解不解开 ——
  游客一进来就看到原因并被告知回主页，不会"填完表单才被拒"。
- 身份判断走 `GET /api/me`（未登录 401）或登录响应里的 `guest` 标记，
  **不做**"试一次写操作看会不会 403"的探测。

> **为什么不把游客口令放进 `classes` 表**：游客在业务上不属于任何班级。
> 混进表里会让后台的班级列表、年级人数汇总、口令批量生成都多出一个假"班级"，
> 还可能被误删误改；而且"表里有一行"就意味着永久开启，"不配即关闭"这条
> 安全默认值就落不了地。放在环境变量里，删掉变量整个功能干净消失，
> 数据库里一个字节都不留。

> 建议把游客口令设成一个**只能看**的独立值（够长、与班级口令不同），
> 并且按"它会被转发出去"来对待。即使泄露，后果也只是多了些只读观众。

### 界面交互（弹窗、动画、局部刷新）

- **不用浏览器原生弹窗。** 全站 84 处 `alert / confirm / prompt` 都已换成自绘弹窗
  （`uiAlert` / `uiConfirm` / `uiPrompt` / `uiToast`）。原生弹窗样式无法控制、在手机上尤其难看。
  弹窗样式由 JS 运行时注入 `<style>`，所以页面自身的样式块不受影响。
- **动画不是瞬变**：入场用 `cubic-bezier` 缓动 + 轻微缩放/位移，按钮带内高光与投影，
  按下时会轻微下沉。
- **局部刷新**：单首歌的审核动作（通过 / 拒绝 / 恢复 / 删除）只把**那一张卡片**
  淡出移除，不再把整个列表重新拉一遍。分类改动因为会连带影响排序（权重参与综合分），
  会重排，但走**安静模式**（不显示"加载中..."、不清屏），观感上没有"整页刷一下"。
- **并发取数**：系统设置页原本串行发 4 个请求（设置 → 公告 → 动态口令 → 管理员），
  现在用 `Promise.all` 并发；待审核页的歌曲列表与举报收件箱也并发取。
  弱网/小屏下体感差别很明显。
- **防止页签内容错位**：几个页签都是异步加载，如果前一个请求还没回来就点了另一个页签，
  **先发的请求可能后到**，把后点页签的内容覆盖掉 —— 表现为"高亮的是黑名单，
  显示的却是系统设置"。现在用自增的"代"计数做守卫：渲染前检查自己是否仍是最新一代，
  不是就直接丢弃。**这是之前实际出现过的一个 bug。**

### 投稿须知

首页显眼位置有「投稿须知」卡片（默认收起，点标题展开），共 9 条，**同时是审核依据**：

1. 中午放学播放 3 首含歌词的音乐，下午上学播放 3 首纯音乐。
2. 不出现含有日语或韩语的歌曲，尽量避免小语种歌曲；英语歌曲可以投稿，但播放比例较小。

5. 不出现 rap，以及底噪、低音、高音过大的歌曲；音游、二次元相关歌曲请尽量少投稿。

### 双端适配（手机切换 / 电脑分栏）

首页的两个榜单在不同屏幕上用不同布局：

- **窄屏（手机，< 900px）**：顶部两个按钮「待审核榜 / 正式榜」切换，一次只显示一栏。
- **宽屏（电脑，≥ 900px）**：自动隐藏切换按钮，**左右两栏同时显示**，`body` 最大宽度放宽到 1080px。

实现要点：`.col{display:none}` + `.col.active{display:block}` 控制窄屏的显隐，
再用 `@media(min-width:900px)` 里 `#rankList{display:grid;grid-template-columns:1fr 1fr}`
把两栏并排、并强制 `.col{display:block}`。

> 原版 `index.html` 的脚本里本来就有 `switchMobileTab`，但它引用的
> `tabPending` / `tabApproved` / `pendingCol` / `approvedCol` 四个元素**在 HTML 里根本不存在**，
> 两栏容器也没有 —— 所以这个功能原版是坏的。现在补齐了 DOM 与样式。

#### 后台的窄屏适配

后台加了「黑名单」页签后变成 **5 个页签**，在手机上是**必然溢出**的：

| | 需要的宽度 |
|---|---|
| 5 个页签的文字 + 内边距 | 约 324px |
| 4 个间隔（10px） | 40px |
| **合计** | **约 364px** |
| 360px 手机的可用宽度（减去 body 左右各 16px） | **约 328px** |

所以 `admin.html` 里追加了一段**只在窄屏生效**的媒体查询：

```css
@media(max-width:560px){
  .tabs{flex-wrap:wrap;gap:8px;}
  .tabs button{width:auto;flex:1 1 auto;min-width:72px;}
  .card .actions{flex-wrap:wrap;}          /* 卡片下方最多有 5~6 个操作按钮 */
  .card .actions button{width:auto;flex:1 1 auto;min-width:72px;}
}
```

试听候选列表的行也加了 `flex-wrap:wrap`，窄屏下按钮会换到第二行。

> **桌面渲染不受影响**：新增样式全部在 `@media` 里，顶层规则与原版逐字节相同。
> 有一条测试专门守着这件事 —— 它会把 `@media` 块摘掉再比对，所以任何
> "溜到顶层的新规则"都会失败。

另外全站检查过：**没有超过手机可用宽度的固定宽度**，容器一律用
`max-width` 限宽而非写死 `width`，所以不会横向溢出。

## 四、视觉风格与双端适配

**没有重写任何 CSS 规则，也没有改类名。** 改动只有两类：

### 1. `body` 背景：让已有的液态玻璃显出来

- 原版背景是一层很淡的灰蓝渐变（`#f0f4f8 → #e2e8f0`）。而原版 CSS 里
  `.card` / `.rank-card` / `#gate` / `.box` / `.header` / `.login-box`
  **本来就有 `backdrop-filter: blur(8~12px)` + 半透明白底 + 亮边** ——
  这就是液态玻璃的配方，但模糊一层几乎没有色差的底面，和白色卡片几乎一样白，
  玻璃质感就"糊"掉了。
- 现在背景换成**浅色底 + 四团柔和光斑**（天蓝 / 靛蓝 / 青绿 / 淡粉，
  多个 `radial-gradient` 叠加），保留原来的灰蓝渐变作为最底层，
  并加 `background-attachment: fixed`。玻璃面模糊一层**有颜色层次**的底面，
  质感立刻出来。
- 底色仍是浅色系（`#eef3f9`），**没有改成深色主题**；所有卡片的
  `backdrop-filter`、圆角、边框、阴影、动画一个都没动。

### 2. `index.html` 新增双端适配规则（只追加，不改原有规则）

新增 `.mobile-tabs` / `.col` / `.col-title` 与一个 `@media(min-width:900px)` 断点，
详见上文「双端适配」。**原有规则一条都没删改**，只是在其后追加。

### 测试怎么守着

1. **`vote.html` / `admin.html`**：`<style>` 去掉 body 规则后必须与原版**逐字节相同**。
2. **`index.html`**：原版**每一条 CSS 规则**都必须仍以原样存在（允许在后面追加新规则，
   但删改任何一条都会失败）。
3. **每个页面**的 `backdrop-filter:blur(...)` 必须都还在，body 背景必须含
   `radial-gradient` 光斑与浅色底。
4. 双端适配必须有四个元素、两个绑定、窄屏单栏 + 宽屏 `grid` 两栏。

## 六、免费套餐相关的两个关键优化

免费版 Pages Functions 有两条硬限制：**单次请求 10ms CPU**、**每天 10 万次调用**。

1. **`_routes.json` 只把 `/api/*` 交给 Functions**，静态页面（HTML/CSS/图片）
   由 CDN 直接返回，不消耗调用额度。少了这一步，每次刷新页面都会烧一次调用。
2. **PBKDF2 迭代次数定为 10000**。实测 5000=1.14ms、10000≈2.9ms、25000=4.75ms、
   50000=9.17ms。管理员改密要算两次哈希，25k 时最坏接近 9.5ms，已经贴着 10ms 上限，
   很容易触发 Error 1102，因此降到 10000。
3. 同理，**批量生成班级口令放在前端逐个调接口**：20 个班级若在服务端一次算完，
   需要 20 次 PBKDF2 ≈ 60ms，必然超限。

## 七、已知问题与限制

- **认证用的是 HttpOnly Cookie，不是 `sessionStorage`。**
  交接文档建议存 `sessionStorage`，但那会让 XSS 直接读到令牌；HttpOnly Cookie
  脚本读不到，安全性明显更好。代价是需要同站 Cookie（本项目前后端同域，没问题）。
- **CSP 里的 `script-src` 含 `'unsafe-inline'`。** 因为按要求保留了内联
  `<script>` 和 `onclick`，无法去掉。所以 CSP 挡不住"页面内联脚本注入"，
  XSS 的主要防线是代码里的 `escapeHtml` 转义。若要彻底收紧，需要把脚本外链化。
- **`sql/001` 不可重复执行**（列已存在会报 `duplicate column name`），这是预期行为；
  重复部署请用增量补丁。
- **改 `AUTH_PEPPER` 会锁死已有班级口令**，见上文第 3 步的说明。
- **音源是第三方公共服务**，随时可能失效。默认 `auto` 会优先 Meting、失败回退
  苹果官方试听（30 秒片段，零配置可用）。若要稳定，建议自建 Meting 并用
  `MUSIC_API_BASE` 指过去。
- **点歌强制从搜索结果里选**。好处是锁定了音源、榜上直接播对的那一版；
  代价是**搜不到的歌就点不了**（冷门曲目、翻唱、纯音乐尤其容易搜不到）。
  目前的退路只有管理员用调试模式提交。若觉得太严，可以把
  `vote.js` 里"必须带 track_id"那一段改成可选。

### 忘记管理员密码怎么办

**先说为什么没有一个"一键重置"的 SQL 文件。**（审计 A1）

以前 `sql/002` 里带两条 `UPDATE`，把管理员口令和 1 号班级口令重置成**固定的、
预计算好的哈希**，用途就是"忘记密码时夺回控制权"。那样做有个根本问题：

> **哈希写在仓库里 = 口令是公开的。** 换成哈希存储并不会让一个已经公开的口令
> 重新变成秘密。

而且它跟着正常迁移流程一起跑，于是**每次重跑迁移都会把已经改过的口令打回公开默认值**，
重置之后也没有撤销既有会话。所以那两条 `UPDATE` 已经删除，并且有测试守着：

- 重跑 001–013 不许改动任何既有凭证（A1 的验收标准）
- 增量迁移里不许出现"把口令设成固定哈希"的语句

**正确做法：用你自己生成的口令重置。**

1. 自己算一条哈希（脚本只打印在终端，**不会写进任何文件**）：

   ```powershell
   $env:ELECTRON_RUN_AS_NODE='1'
   & "D:\dsh\DSH Desktop\DSH Desktop.exe" "_harness\gen-credentials.mjs" "你的新口令"
   ```

   （这一条需要你本地有那份 `_harness/` 开发目录。没有的话，直接看第 3 步的替用办法。）

2. 把打印出来的哈希粘进 D1 控制台，**并且一并撤销既有会话**：

   ```sql
   UPDATE admins SET password = '粘贴上一步的哈希' WHERE username = 'admin';
   DELETE FROM sessions WHERE subject = 'admin';
   ```

3. **没有开发目录时的替用办法**：本项目在登录时兼容历史明文口令，
   首次登录成功后会**自动改成哈希**回写。所以紧急情况下可以直接：

   ```sql
   UPDATE admins SET password = '你自己临时设的口令' WHERE username = 'admin';
   DELETE FROM sessions WHERE subject = 'admin';
   ```

   登录一次之后它就会被自动哈希化。**但请务必在登录后立刻到
   「系统设置 → 修改管理员密码」再改一次** —— 明文在库里停留的这段时间是暴露面。

> 无论走哪条路，**都不要把重置后的哈希提交进仓库**。
> 提交了就等于把口令公开，这正是 A1 要修的问题。

**班级口令忘了**不需要这样绕：管理员登录后到
「系统设置 → 班级管理」就能看到（需要配置 `AUTH_PEPPER`）并重新生成。

## 部署后必做（本仓库是公开的）

**这个仓库是开源的，所以里面的任何默认值都是全世界都知道的。**
这一节列的每一步都不是"建议"，而是"不做就等于把后台挂在公网上"。

### 1. 立刻改掉示例管理员口令

`000_reset_database.sql` 里的示例口令是为了让你能第一次登录进去。
**公开仓库里的默认口令不能用**，所以系统**默认拒绝**用示例口令登录管理员
（只有显式配置 `ALLOW_DEFAULT_ADMIN_PASSWORD=1` 才放行，那是给本地测试用的）。

请按上面的「忘记管理员密码怎么办」生成一条**你自己的**口令哈希并写入，
然后用新口令登录，到「系统设置 → 修改管理员密码」再确认一次。

### 2. 立刻改掉示例班级口令

同理，`yczx2026` 也是公开的。高级管理员登录后到
「系统设置 → 班级管理」批量生成或逐个修改。

### 3. 配置 AUTH_PEPPER

它是班级口令查找索引与可查看密文的主密钥。**不配的话**：

- 「查看班级口令」功能会被自动禁用（因为密文是用源码里公开的占位密钥加的，
  能解开等于没加密）；
- 查找索引也会用公开的占位密钥，等于少一层保护。

请设一个足够长的随机串，并且**不要随意更换**（换了已有口令的索引会失效，
恢复办法是管理员登录后重置班级口令）。

### 4. 配好人机校验（可选，但建议）

`RECAPTCHA_SITE_KEY` + `RECAPTCHA_SECRET` 两个都要配才生效。
默认域名走 `www.recaptcha.net`（`www.google.com` 在中国大陆不可达）。

### 5. 保持调试入口关闭

`DEBUG_LOGIN` 默认关闭。它能让高级管理员在一次登录里不限次、不查重地
往真实歌曲表写数据（用于压测投稿逻辑）—— 生产环境请保持关闭。

### 6. 想开游客模式就单独设一个口令

不设 `GUEST_PASSWORD` 就**没有**游客模式（默认关闭）。要开的话，
请设一个只在游客模式里用的独立口令 —— 别把班级口令复制一份进去：
游客口令大概率会被转发到班级群、家长群，它能做的事越少越好（它只能看排行）。

### 7. 不要把密钥提交进仓库

仓库里已经放了 `.gitignore`，会挡掉 `.env` / `.dev.vars` / 本地数据库导出等。
环境变量请只配在 Cloudflare Pages 的 Environment variables 里。

> 有一条测试会扫描交付包，确认里面**不含**常见密钥格式
> （`sk-` / `ghp_` / `AKIA` / `Bearer` 长串），并且迁移 SQL 里
> **不含任何可用的固定口令哈希**。
